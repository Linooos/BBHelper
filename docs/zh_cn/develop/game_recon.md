## 5. 使魔探险

- 标题栏：`已接取的探险数 N/10`、`使魔探险将于每日4:00刷新`
- 列表按评级 S / A / B … 排列

条目的四种状态（右侧那一列的文字是判定依据）：

| 状态 | 右侧文字 | 含义 |
| --- | --- | --- |
| 已完成待领 | **点击领取奖励** | 时间到了，可领奖 |
| 已接受待编队 | **点击选择使魔** | 已接受，但还没配使魔，**不能出发** |
| 进行中 | **剩余时间：HH:MM:SS** | 已派出，倒计时中 |
| 未接受 | 需要时间：HH:MM:SS | 还在池子里（需先接受） |

### 接取/派出流程

点「点击选择使魔」会打开**使魔编队界面**：

- 顶部：`特性：` 两个槽、`使魔：` 四个槽、`成功率：0.00%`
- 中部：使魔卡片网格，点击可勾选
- 底部两个按钮：**一键派遣**（自动配齐）与**出发**（派出）

实测：点「一键派遣」后特性槽与四个使魔槽全部填满，
**成功率 0.00% → 100.00%**。此时再点「出发」才会真正派出，
界面回到列表，该条目变成「剩余时间」。**不做一键派遣直接出发成功率是 0，不应出发。**

### 关键行为

- **领取已完成的探险即算「收回」**，满足每日任务「星辰的彼方」，
  所以该任务不需要真的去接受新探险。
- 领取会**消耗**已接取数（实测 8/10 → 7/10 → 6/10 → 5/10 → 4/10）。
- 「已接取的探险数 N/10」**不随「补齐使魔并派出」增加**，
  推测它统计的是当日从池子里「接受」的配额，而非当前占用数。
- 条目会随接取/派出**自动上浮**，因此不需要滚动列表——
  循环点「点击选择使魔」直到匹配不到即可（用户实测确认）。

### 通关特征

战斗胜利后出现**结算画面**，最可靠的判据是 OCR 到 **`战斗结算`** 这个字符串：

```
[战斗结算]                      ← 通关判据（唯一、稳定）
挑战时间 598s   受击次数 0   最大连击 15
奖励图标若干（金币 / 水晶 / 经验道具）
角色等级 544  经验 +1000
[确定]  ← (825, 613)
```

### 已验证的操作能力（MaaFramework）

输入走 **MaaTouch** 通道，以下全部实测 `success: true`：

| 能力 | 结论 | 证据 |
| --- | --- | --- |
| `TouchDown` / `TouchMove` / `TouchUp` | ✅ 可用 | 三个动作均成功执行 |
| 摇杆按住驱动角色移动 | ✅ | 背景与月亮持续滚动 |
| **按住期间跑识别** | ✅ | hold 期间 OCR 成功读到 HP 文本 |
| **多指并发** | ✅ | `contact=1` 触摸不打断 `contact=0` 的按住，角色持续移动 |
| 攻击自动生效 | ✅ | 用户确认看到攻击动画；实测结算「最大连击 15」 |

**关键结论**：「按住」在 MaaFramework 里是**持久状态**——`TouchDown` 后不 `TouchUp`，
触点就一直按着，中间可以插任意多个识别节点。**因此「一边操作一边轮询识别」不需要开线程**：

```
TouchDown(摇杆) → TouchMove(方向) → [循环: 识别通关特征 → 未通关则维持按键] → TouchUp
```

多指靠 `contact` 区分：`0` = 摇杆，`1` = 攻击键。

### 通关判据（battle.json 的 Battle_ClearCheck）

用「文字 + 画面」四条判据做 `Or`，命中任一即判战斗结束：

| 顺序 | 判据 | ROI | 出现时机 |
| --- | --- | --- | --- |
| ① | OCR `战斗结算` | [540,110,220,50] | 最晚，但会停留到点「确定」 |
| ② | OCR `胜利` | [460,425,360,110] | 最早，只闪很短 |
| ③ | TemplateMatch 胜利图案 | [300,160,620,290] | 同上（兜底） |

> `Or` 的语义是「命中第一个即成功，后续不再识别」，所以顺序即优先级。
> 模板 `image/Battle/VictoryFigure.png` 裁自实机截图，避开了玩家角色与下方文字，
> 但仍带入了部分关卡背景，**换关卡可能失配**——所以它只排第三顺位。

### 已验证可通关的打法（方案 A）

**按住摇杆向右 + 按住电锯键 (993, 618)**，一直保持，直到通关判据命中，然后**立即释放双手指**。

实跑两次验证：

| | 挑战时间 | 受击次数 | 最大连击 | 通关判据命中项 |
| --- | --- | --- | --- | --- |
| 手动试探 | 598s | 0 | 15 | （人工观察） |
| 脚本跑 | **81s** | **0** | 27 | OCR `胜利`（第 ② 条） |

战斗循环约 8 轮（≈10 秒）后判据命中并释放，**无卡住的输入**。

> ⚠️ `TouchDown` 的 `auto_up` 默认是 `false`，任务中止时**不会自动抬起手指**。
> 战斗脚本里必须显式设 `auto_up: true`，否则中断后角色会一直朝一个方向跑。
